Docker 核心技术原理

🔒

命名空间 (Namespaces)

实现进程、网络、挂载点等资源的隔离，每个容器拥有独立的视图

PID Namespace: 进程ID隔离
NET Namespace: 网络接口隔离
MNT Namespace: 挂载点隔离
⚖️

控制组 (Cgroups)

限制和隔离应用对CPU、内存、磁盘IO等资源的使用

cpu: CPU 时间片分配
memory: 内存使用限制
blkio: 块设备IO限制
🔄

联合文件系统 (Union FS)

将多个文件系统合并到单一挂载点，实现镜像分层和写时复制

AUFS: 高级多层统一文件系统
OverlayFS: 轻量级联合文件系统
DeviceMapper: 块级存储管理

Docker 目录结构详解

📁 为什么了解 Docker 目录结构很重要？

Docker 在主机上创建了多个目录用于存储镜像、容器、卷、网络等数据。了解这些目录的结构和用途可以帮助您：

  • 有效管理存储空间
  • 快速定位和备份重要数据
  • 解决存储相关问题
  • 优化 Docker 性能
  • 进行故障排查

查看 Docker 根目录

# 查看 Docker 根目录位置
docker info | grep "Docker Root Dir"

# 输出示例（Linux/Mac）：
# Docker Root Dir: /var/lib/docker

# Windows 输出示例：
# Docker Root Dir: C:\ProgramData\Docker

# 查看目录大小
du -sh /var/lib/docker/*

Docker 完整目录结构

/var/lib/docker/                      # Docker 根目录
├── aufs/                             # AUFS 存储驱动（如果使用 AUFS）
├── buildkit/                         # BuildKit 构建缓存
│   ├── cache.db                      # BuildKit 缓存数据库
│   └── snapshots.db                  # BuildKit 快照数据库
├── containers/                       # 容器数据
│   ├── {container-id}/               # 单个容器目录
│   │   ├── config.v2.json            # 容器配置
│   │   ├── hostconfig.json           # 容器主机配置
│   │   ├── hostname                  # 容器主机名
│   │   ├── hosts                     # 容器 hosts 文件
│   │   ├── resolv.conf               # DNS 配置
│   │   └── ...                       # 其他容器文件
├── image/                            # 镜像数据
│   ├── imagedb.json                  # 镜像数据库
│   ├── layerdb/                      # 镜像层数据库
│   │   └── sha256/                   # 按 SHA256 哈希组织的层
│   └── ...
├── network/                          # 网络配置
│   └── files/
│       ├── network-config.db         # 网络配置数据库
│       └── network-state.db          # 网络状态数据库
├── plugins/                          # Docker 插件
├── swarm/                            # Swarm 集群配置
├── tmp/                              # 临时文件
├── trust/                            # 内容信任配置
├── volumes/                          # 命名卷数据
│   └── {volume-hash}/                # 单个卷目录
└── ...                               # 其他文件和目录

关键目录说明

  • /var/lib/docker/containers/: 存放所有容器的配置和日志文件
  • /var/lib/docker/image/: 存放镜像元数据和层信息
  • /var/lib/docker/volumes/: 存放命名卷的数据
  • /var/lib/docker/network/: 存放网络配置信息
  • /var/lib/docker/buildkit/: 存放 BuildKit 构建缓存

Docker 网络详解

🌐 Docker 网络概述

Docker 网络功能允许容器之间以及容器与主机之间的通信。Docker 提供了多种网络驱动，每种都有其特定的用途和功能。

查看网络

# 列出所有网络
docker network ls

# 查看特定网络详情
docker network inspect bridge

# 查看容器网络配置
docker inspect CONTAINER_NAME

创建自定义网络

# 创建桥接网络
docker network create my-bridge-network

# 创建覆盖网络（用于 Swarm）
docker network create --driver overlay my-overlay-network

# 创建 MACVLAN 网络
docker network create -d macvlan --subnet=172.16.86.0/24 --gateway=172.16.86.1 -o parent=eth0 pub-net

# 创建 IPVLAN 网络
docker network create -d ipvlan --subnet=192.168.1.0/24 --gateway=192.168.1.1 -o parent=eth0 ipvlan-net

网络驱动类型

  • Bridge: 默认网络驱动，适用于单主机上的容器通信
  • Host: 移除容器和 Docker 主机之间的网络隔离
  • Overlay: 用于连接多个 Docker 守护进程，适用于 Swarm
  • Macvlan: 为容器分配 MAC 地址，使其外观像物理设备
  • None: 禁用所有网络
  • 第三方插件: 其他网络实现

使用自定义网络

# 运行容器时指定网络
docker run -d --name container1 --network my-bridge-network nginx

# 将运行中的容器连接到网络
docker network connect my-bridge-network container2

# 断开容器与网络的连接
docker network disconnect my-bridge-network container1

# 使用自定义网络运行多个容器
docker run -d --name web --network my-bridge-network nginx
docker run -d --name db --network my-bridge-network mysql:8.0

Docker Compose 网络配置

version: '3.8'

services:
  web:
    image: nginx
    networks:
      - frontend
      - backend

  api:
    image: myapi
    networks:
      - backend

  db:
    image: postgres
    networks:
      - backend

networks:
  frontend:
    driver: bridge
  backend:
    driver: bridge
    internal: true  # 禁止外部访问

网络最佳实践

  • 使用自定义网络而非默认桥接网络
  • 使用有意义的网络名称
  • 根据安全需求分离网络（例如，前端和后端）
  • 定期清理未使用的网络
  • 使用内部网络限制对外访问

Docker 数据卷详解

💾 Docker 数据卷概述

数据卷是 Docker 中用于持久化数据的机制，它独立于容器生命周期，即使容器被删除，数据卷中的数据仍然存在。

数据卷操作命令

# 创建数据卷
docker volume create my-volume

# 列出所有数据卷
docker volume ls

# 查看数据卷详情
docker volume inspect my-volume

# 删除数据卷
docker volume rm my-volume

# 清理未使用的数据卷
docker volume prune

# 查看所有数据卷（包括未使用的）
docker volume ls -q | xargs docker volume inspect

挂载数据卷到容器

# 使用命名卷
docker run -d --name my-container -v my-volume:/app/data nginx

# 使用匿名卷
docker run -d --name my-container -v /app/data nginx

# 使用绑定挂载（主机目录）
docker run -d --name my-container -v /host/path:/container/path nginx

# 使用临时文件系统（内存中）
docker run -d --name my-container --tmpfs /app/data nginx

# 只读挂载
docker run -d --name my-container -v my-volume:/app/data:ro nginx

# 设置挂载选项
docker run -d --name my-container -v my-volume:/app/data:rw,Z nginx

数据卷类型

  • 命名卷: Docker 管理的持久化存储，存储在主机的特定位置
  • 匿名卷: 没有指定名称的卷，由 Docker 自动分配名称
  • 绑定挂载: 挂载主机文件系统中的文件或目录到容器
  • 临时文件系统: 挂载到内存中的临时文件系统（tmpfs）

Docker Compose 中的数据卷

version: '3.8'

services:
  web:
    image: nginx
    volumes:
      # 命名卷
      - web-data:/usr/share/nginx/html
      # 绑定挂载
      - ./html:/usr/share/nginx/html
      # 匿名卷
      - /tmp/cache
      # 只读绑定挂载
      - ./config:/etc/nginx/configs:ro
      # 临时文件系统
      - type: tmpfs
        target: /run
        tmpfs:
          size: 100M

  db:
    image: postgres:15
    volumes:
      # 命名卷用于数据库持久化
      - db-data:/var/lib/postgresql/data
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password

volumes:
  web-data:
  db-data:
    driver: local
    driver_opts:
      type: none
      o: bind
      device: /opt/postgres-data

数据卷备份和恢复

# 创建备份容器
docker run --rm -v my-volume:/volume -v $(pwd):/backup alpine tar czf /backup/backup.tar.gz -C /volume .

# 恢复备份
docker run --rm -v my-volume:/volume -v backup-container:/backup alpine tar xzf /backup/backup.tar.gz -C /volume

# 使用专门的备份工具
docker run --rm -it -v my-volume:/data -v backup-container:/backup alpine tar -cvf - -C /data . | tar -xvf - -C /backup

# 从主机备份
sudo tar -czf backup.tar.gz -C /var/lib/docker/volumes/my-volume/_data .

数据卷最佳实践

  • 使用命名卷而非绑定挂载，以获得更好的可移植性
  • 为生产环境使用专用的存储解决方案
  • 定期备份重要数据卷
  • 使用卷驱动程序扩展功能（如加密、远程存储）
  • 合理规划卷的权限和访问模式

使用 Docker Scout 进行安全扫描

# 扫描镜像漏洞
docker scout cves myapp:latest

# 快速漏洞扫描
docker scout quickview myapp:latest

# 生成 SBOM（软件物料清单）
docker scout sbom myapp:latest --output sbom.json

# 查看镜像详情和依赖关系
docker scout repo myapp:latest

# 比较镜像差异
docker scout compare old:latest new:latest

# CI/CD 集成（失败如果发现高危漏洞）
docker scout cves --exit-code 1 --severity high,critical myapp:latest

使用 BuildKit 2.0 分布式构建

# 设置分布式构建缓存
export BUILDKIT_REMOTE_CACHE=type=registry,ref=myregistry.com/cache

# 使用远程构建器
docker buildx build \
  --builder=my-builder \
  --cache-from=type=registry,ref=myregistry.com/cache \
  --cache-to=type=registry,ref=myregistry.com/cache,mode=max \
  -t myapp:latest \
  .

# 创建远程构建器
docker buildx create --name remote-builder \
  --driver=docker-container \
  --driver-opt image=moby/buildkit:latest \
  --bootstrap

# 并行构建多架构镜像
docker buildx build \
  --platform linux/amd64,linux/arm64,linux/arm/v7 \
  -t myapp:multiarch \
  --push .

Dockerfile 实践

Dockerfile 最佳实践

  • 使用 .dockerignore 文件排除不必要的文件
  • 选择合适的基础镜像（如 Alpine）以减小体积
  • 合并 RUN 指令以减少镜像层数
  • 使用构建缓存优化构建速度
  • 设置 HEALTHCHECK 检查容器健康状态

优化的 Dockerfile 示例

# 使用特定版本的基础镜像
FROM node:18-alpine

# 设置工作目录
WORKDIR /app

# 只复制 package 文件以利用构建缓存
COPY package*.json ./

# 安装依赖
RUN npm ci --only=production

# 复制应用代码
COPY . .

# 创建非 root 用户
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nodejs -u 1001

# 切换到非 root 用户
USER nodejs

# 暴露端口
EXPOSE 3000

# 健康检查
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
    CMD curl -f http://localhost:3000/health || exit 1

# 启动命令
CMD ["npm", "start"]

version: '3.8'

    build: .
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production

      - ./logs:/app/logs
    depends_on:
      - db
      - redis
    restart: unless-stopped
    networks:
      - app-network
    deploy:
      resources:
        limits:
          cpus: '0.5'
          memory: 512M

    image: postgres:15-alpine
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    restart: unless-stopped
    networks:
      - app-network

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    restart: unless-stopped
    networks:
      - app-network

networks:
  app-network:
    driver: bridge

volumes:
  postgres_data:
  redis_data:

WASM 容器

什么是 WASM 容器？

WebAssembly (WASM) 容器是 Docker 的革命性特性。它将 WASM 模块作为容器运行，提供接近原生的性能、极小的镜像大小（通常 <1MB）和更强的隔离性。

为什么要引入 WASM 容器？

  • 极致性能：毫秒级启动，比传统容器快 10-100 倍
  • 极小体积：镜像通常 <1MB，比传统容器小 100-1000 倍
  • 高安全性：基于能力的安全模型，更强的隔离性
  • 跨平台：一次构建，随处运行（Linux、macOS、Windows）
  • 多语言支持：支持 Rust、Go、Python、JavaScript 等语言
  • 低资源占用：内存占用通常是传统容器的 10%
  • 无服务器友好：完美适配 FaaS 和边缘计算场景

WASM 容器最佳实践

  • 使用轻量级运行时如 WasmEdge 或 Wasmer
  • 优化 WASM 模块大小以提高性能
  • 合理配置资源限制
  • 注意 WASM 模块的兼容性
  • 监控 WASM 容器的性能指标

WASM 容器示例

# 启用 WASM 支持（需要 Docker 27.0+）
export DOCKER_CLI_EXPERIMENTAL=enabled

# 运行 WASM 容器
docker run --runtime=wasm --rm -p 8080:8080 \
  wasmcloud/http-hello-world

# 查看 WASM 运行时
docker info | grep -i wasm

# 使用 Docker Compose 运行 WASM 服务
docker compose --compatibility up -d

# 构建 WASM 应用
docker build -t my-wasm-app -f Dockerfile.wasm .

# 检查 WASM 运行时
docker info | grep -i wasm

WASM vs 传统容器对比

# 传统容器
镜像大小：~150MB (Node.js 应用)
启动时间：~1-2 秒
内存占用：~50-100MB
隔离性：Linux 命名空间 + cgroups

# WASM 容器
镜像大小：~500KB - 1MB
启动时间：~10-50ms
内存占用：~5-10MB
隔离性：WASM 能力模型 + 沙箱

# 性能提升：
- 镜像拉取速度：提升 100-200 倍
- 冷启动时间：提升 20-100 倍
- 资源利用率：提升 5-10 倍

# 使用 Dagger 进行 AI 驱动的构建
# dagger/ci.mts
import Client from "@dagger.io/dagger";

async function buildAndTest() {
  const client = new Client();
  
  try {
    const source = client.host().directory("./");
    
    // AI 优化的构建流程
    const build = await client
      .container()
      .from("node:18-alpine")
      .withDirectory("/src", source)
      .withWorkdir("/src")
      .withExec(["npm", "ci"])
      .withExec(["npm", "run", "build"])
      .directory("./dist");
    
    // AI 驱动的安全扫描
    const scanResult = await client
      .container()
      .from("aquasec/trivy:latest")
      .withMountedDirectory("/app", source)
      .withExec(["filesystem", "--security-checks", "vuln,config,secret", "/app"])
      .stdout();
    
    console.log(scanResult);
    
    // 返回构建产物
    return build;
  } finally {
    await client.close();
  }
}

buildAndTest();

# 运行 AI 优化的构建
