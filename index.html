📖 Docker 核心概念

理解 Docker 的基础概念是掌握容器技术的关键

📦

镜像 (Image)

只读模板，包含运行应用所需的代码、运行时、库和设置。采用分层存储，支持高效复用。

docker pull nginx:latest
🎯

容器 (Container)

镜像的运行实例，是独立的、可执行的软件单元。容器之间相互隔离，但共享主机内核。

docker run -d -p 80:80 nginx
📝

Dockerfile

定义镜像构建过程的文本文件，包含一系列指令，Docker 按这些指令组装镜像。

FROM node:18
COPY . /app
CMD ["npm", "start"]
🎼

Docker Compose

定义和运行多容器应用的工具，使用 YAML 文件配置应用服务、网络和数据卷。

docker-compose up -d

架构说明

⚔️

Dagger

代码定义的 CI/CD 引擎，支持 AI 优化的构建管道

代码定义 AI 优化 多语言 
// dagger/ci.ts
import Client from "@dagger.io/dagger";

async function build() {
  const client = new Client();
  
  const result = await client
    .container()
    .from("node:18-alpine")
    .withDirectory("/src", client.host().directory("./"))
    .withWorkdir("/src")
    .withExec(["npm", "ci"])
    .withExec(["npm", "test"])
    .withExec(["npm", "run", "build"])
    .directory("./dist");
    
  return result;
}

📝 Dockerfile 最佳实践 (2026)

遵循最佳实践，创建高效、安全的 Docker 镜像

2026 标准 Dockerfile 示例

# syntax=docker/dockerfile:1.7

# 使用特定版本的轻量级基础镜像
FROM node:20-alpine3.19 AS base

# 设置工作目录
WORKDIR /app

# 安装依赖时使用缓存加速
FROM base AS deps
RUN --mount=type=cache,target=/root/.npm \
    npm pkg set scripts.prepare="" && \
    npm ci --only=production

# 构建阶段
FROM base AS builder
RUN --mount=type=cache,target=/root/.npm \
    npm ci && \
    npm run build

# 生产镜像
FROM base AS production

# 创建非 root 用户
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nodejs -u 1001

# 复制依赖和生产文件
COPY --from=deps /app/node_modules ./node_modules
COPY --from=builder /app/dist ./dist
COPY package.json ./

# 设置用户和权限
USER nodejs

# 健康检查
HEALTHCHECK --interval=30s --timeout=3s \
  --start-period=5s --retries=3 \
  CMD wget --quiet --tries=1 --spider \
      http://localhost:3000/health || exit 1

EXPOSE 3000

CMD ["node", "dist/server.js"]

关键实践要点

✅
使用多阶段构建

分离构建环境和运行环境，减小最终镜像大小

✅
利用构建缓存

使用--mount=type=cache加速依赖安装

✅
非 root 用户运行

提高容器安全性，防止权限提升攻击

✅
健康检查

监控容器状态，自动重启异常容器

✅
使用 .dockerignore

排除不必要的文件，减小构建上下文

✅
固定版本标签

避免使用latest，确保构建可重复

🎼 Docker Compose 实战

使用 Compose 定义和运行多容器应用

完整的 Compose 配置示例

name: myapp

services:
  web:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        - NODE_ENV=production
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DATABASE_URL=postgres://user:pass@db:5432/myapp
      - REDIS_URL=redis://redis:6379
    volumes:
      - ./logs:/app/logs
      - web-static:/app/public
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy
    networks:
      - frontend
      - backend
    deploy:
      resources:
        limits:
          cpus: '1.5'
          memory: 1G
        reservations:
          cpus: '0.25'
          memory: 256M
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", \
             "http://localhost:3000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: user
      POSTGRES_PASSWORD: ${DB_PASSWORD:-secure_password}
    volumes:
      - db-data:/var/lib/postgresql/data
      - ./backups:/backups
    networks:
      - backend
    deploy:
      resources:
        limits:
          cpus: '1'
          memory: 1G
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user -d myapp"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    command: redis-server --appendonly yes
    volumes:
      - redis-data:/data
    networks:
      - backend
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5

networks:
  frontend:
    driver: bridge
  backend:
    driver: bridge
    internal: true

volumes:
  db-data:
  redis-data:
  web-static:

🔮 WASM 容器 - 下一代容器技术

WebAssembly 容器带来极致性能和安全性

什么是 WASM 容器？

WASM（WebAssembly）容器是 Docker 的革命性特性，将 WASM 模块作为容器运行，提供：

  • 极致性能：毫秒级启动，比传统容器快 10-100 倍
  • 极小体积：镜像通常 <1MB，比传统容器小 100-1000 倍
  • 高安全性：基于能力的安全模型，更强的隔离性
  • 跨平台：一次构建，随处运行
  • 多语言支持：支持 Rust、Go、Python、JavaScript 等

性能对比

指标 传统容器 WASM 容器 提升
镜像大小 ~150MB ~500KB 300x
启动时间 ~1-2s ~10-50ms 40x
内存占用 ~50-100MB ~5-10MB 10x
冷启动 秒级 毫秒级 100x

运行 WASM 容器

# 启用 WASM 支持（Docker 27.0+）
export DOCKER_CLI_EXPERIMENTAL=enabled

# 运行 WASM 容器
docker run --runtime=wasm --rm -p 8080:8080 \
  wasmcloud/http-hello-world

# 构建 WASM 应用
docker buildx build \
  --platform wasi/wasm \
  -t my-wasm-app \
  -f Dockerfile.wasm .

# 查看 WASM 运行时
docker info | grep -i wasm

深入了解 Docker 最新版本带来的强大功能

BuildKit - 现代构建引擎

v23.0+

BuildKit 提供强大的构建性能和灵活性：

  • 分布式构建：支持远程构建器，团队共享构建缓存
  • 智能缓存：多层缓存策略，显著加速重复构建
  • 并行执行：独立步骤自动并行，最大化 CPU 利用
  • 缓存挂载：用于依赖管理的高效缓存
  • 多平台构建：单次构建多个架构的镜像
# 创建远程构建器
docker buildx create \
  --name remote-builder \
  --driver=docker-container \
  --bootstrap

# 使用共享缓存构建
docker buildx build \
  --builder=remote-builder \
  --cache-from=type=registry,ref=myorg/cache \
  --cache-to=type=registry,ref=myorg/cache,mode=max \
  -t myapp:latest .

# 多平台构建
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t myapp:multiarch \
  --push .

Docker Scout 2.0 - AI 驱动的安全

v27.0+

Docker Scout 2.0 提供全面的安全保障：

  • 实时漏洞扫描：持续监控 CVE 数据库
  • AI 修复建议：智能推荐最优修复方案
  • SBOM 生成：自动生成软件物料清单
  • 合规检查：自动检查合规要求
# 完整安全扫描
docker scout cves \
  --severity critical,high \
  --exit-code 1 \
  myapp:latest

# 生成 SBOM 报告
docker scout sbom \
  --format spdx-json \
  --output sbom.json \
  myapp:latest

# 比较镜像安全状态
docker scout compare \
  --from myapp:v1 \
  --to myapp:v2

# CI/CD 集成
docker scout quickview \
  --format markdown \
  myapp:latest

容器安全增强 - 零信任架构

v27.0+

2026 版 Docker 引入了多项安全增强：

  • 镜像签名：基于 Cosign 的原生签名支持
  • 内容信任：只运行已签名的镜像
  • 密钥管理：集成云 KMS 和硬件密钥
  • 供应链安全：SLSA 合规性检查
# 启用内容信任
export DOCKER_CONTENT_TRUST=1

# 签名镜像
cosign sign \
  --key cosign.key \
  myregistry.com/myapp:latest

# 验证签名
cosign verify \
  --key cosign.pub \
  myregistry.com/myapp:latest

# 生成 SLSA 证明
cosign generate-slsa-provenance \
  myapp:latest
