🔍 Docker Scout - AI 驱动的安全分析

实时监控镜像安全状态，自动识别和修复漏洞

核心功能

  • 漏洞扫描：实时扫描 CVE 数据库，识别镜像中的安全漏洞
  • SBOM 生成：自动生成软件物料清单，满足合规要求
  • AI 修复建议：智能推荐最优修复方案，评估影响范围
  • 镜像比较：对比不同版本镜像的安全状态变化
  • CI/CD 集成：在流水线中自动阻断不安全镜像
  • 许可证合规：检测开源许可证合规风险

快速开始

# 登录 Docker Hub（启用 Scout）
docker login

# 快速扫描镜像
docker scout quickview myapp:latest

# 详细漏洞扫描
docker scout cves myapp:latest

# 只扫描高危和严重漏洞
docker scout cves \
  --severity HIGH,CRITICAL \
  myapp:latest

# 生成 SBOM 报告（SPDX 格式）
docker scout sbom \
  --format spdx-json \
  --output sbom.json \
  myapp:latest

# 比较两个镜像的安全差异
docker scout compare \
  --from myapp:v1.0 \
  --to myapp:v1.1

# CI/CD 中自动阻断（发现高危漏洞时失败）
docker scout cves \
  --exit-code 1 \
  --severity HIGH,CRITICAL \
  --only-fixed \
  myapp:latest

⚔️ Dagger - 代码定义的 CI/CD

使用编程语言定义 CI/CD 管道，AI 优化构建流程

什么是 Dagger？

Dagger 是一个可编程的 CI/CD 引擎，允许你使用任何编程语言编写 CI/CD 管道。它运行在容器中，确保一致性和可重复性。

  • 代码定义：使用 TypeScript、Python、Go 等编写管道
  • AI 优化：AI 分析构建模式，自动优化执行顺序
  • 本地测试：在本地运行和调试 CI/CD 管道
  • 云端执行：无缝部署到任何 CI 平台
  • 缓存优化：智能缓存，加速重复构建

TypeScript 示例 - 完整的 CI/CD 管道

// ci.ts - 使用 TypeScript 定义的 CI/CD 管道
import Client from "@dagger.io/dagger";

async function ci() {
  const client = new Client();

  try {
    // 获取源代码
    const source = client.host().directory("./");

    // 定义构建容器
    const build = client
      .container()
      .from("node:20-alpine")
      .withDirectory("/src", source)
      .withWorkdir("/src")
      // 使用缓存加速依赖安装
      .withMountedCache("/root/.npm", client.cacheVolume("npm"))
      .withExec(["npm", "ci"])
      // 运行测试
      .withExec(["npm", "test"])
      // 运行构建
      .withExec(["npm", "run", "build"])
      // 获取构建产物
      .directory("./dist");

    // 安全扫描
    const scan = client
      .container()
      .from("aquasec/trivy:latest")
      .withMountedDirectory("/app", source)
      .withExec([
        "fs",
        "--security-checks", "vuln,config,secret",
        "--format", "table",
        "/app"
      ])
      .stdout();

    console.log("安全扫描结果:", scan);

    // 构建生产镜像
    const image = client
      .container()
      .from("node:20-alpine")
      .withDirectory("/app", build)
      .withExec(["npm", "install", "--production"])
      .withExposedPort(3000)
      .withExec(["node", "dist/server.js"]);

    // 推送镜像
    const addr = await image
      .withRegistryAuth("docker.io", process.env.DOCKER_USER, process.env.DOCKER_PASS)
      .publish("docker.io/myuser/myapp:latest");

    console.log("镜像已推送到:", addr);

  } finally {
    await client.close();
  }
}

ci().catch(console.error);

Python 示例 - AI 优化的构建

# ci.py - 使用 Python 定义的 CI/CD 管道
import dagger
import asyncio

async def build():
    async with dagger.Connection() as client:
        # 获取源代码
        source = client.host().directory("./")

        # 构建应用
        build = (
            client.container()
            .from_("python:3.12-slim")
            .with_directory("/src", source)
            .with_workdir("/src")
            # 使用缓存加速 pip 安装
            .with_mounted_cache("/root/.cache/pip", client.cache_volume("pip"))
            .with_exec(["pip", "install", "-r", "requirements.txt"])
            .with_exec(["pytest", "tests/"])
            .with_exec(["python", "-m", "build"])
        )

        # 运行安全扫描
        scan = (
            client.container()
            .from_("aquasec/trivy:latest")
            .with_mounted_directory("/app", source)
            .with_exec([
                "fs",
                "--security-checks", "vuln,config,secret",
                "/app"
            ])
            .stdout()
        )

        print(await scan)

        # 构建并推送镜像
        image = (
            client.container()
            .from_("python:3.12-slim")
            .with_directory("/app", build.directory("./dist"))
            .with_exposed_port(8000)
        )

        addr = await image.publish(
            "docker.io/myuser/myapp:latest",
            platform="linux/amd64"
        )

        print(f"镜像已推送到：{addr}")

asyncio.run(build())

AI Dockerfile 生成器

生成方法

方法一：Ask Gordon（Docker AI 助手）

# 启动 Ask Gordon 交互界面
docker ai

# 在 Gordon 中输入自然语言请求

    adduser -S nodejs -u 1001

HEALTHCHECK --interval=30s --timeout=3s \
  --start-period=5s --retries=3 \
  CMD wget -q --spider http://localhost:3000/health || exit 1

AI 优化建议示例

优化前

FROM node:latest
WORKDIR /app
COPY . .
RUN npm install
EXPOSE 3000
CMD ["npm", "start"]
问题：
  • ❌ 使用 latest 标签，构建不可重复
  • ❌ 没有利用构建缓存
  • ❌ 以 root 用户运行，不安全
  • ❌ 没有健康检查
  • ❌ 镜像体积大

AI 优化后

# syntax=docker/dockerfile:1.7
FROM node:20-alpine3.19 AS base
WORKDIR /app

FROM base AS deps
RUN --mount=type=cache,target=/root/.npm \
    npm ci --only=production

FROM base AS production
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nodejs -u 1001
COPY --from=deps /app/node_modules ./node_modules
COPY . .
USER nodejs
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=3s \
  --start-period=5s --retries=3 \
  CMD wget -q --spider http://localhost:3000/health || exit 1
CMD ["node", "server.js"]
改进：
  • ✅ 固定版本标签
  • ✅ 使用 Alpine 减小体积
  • ✅ 利用构建缓存
  • ✅ 非 root 用户运行
  • ✅ 添加健康检查
  • ✅ 多阶段构建

🔄 CI/CD 集成

在 CI/CD 流水线中集成 AI 工具

GitHub Actions 示例

name: Docker CI/CD with AI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build-and-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Login to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKER_USER }}
          password: ${{ secrets.DOCKER_PASS }}

      - name: Build with BuildKit
        uses: docker/build-push-action@v5
        with:
          context: .
          push: false
          tags: myapp:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
          build-args: |
            BUILDKIT_INLINE_CACHE=1

      - name: Run Docker Scout scan
        uses: docker/scout-action@v1
        with:
          command: cves
          image: myapp:${{ github.sha }}
          severity: HIGH,CRITICAL
          exit-code: true
          only-fixed: true

      - name: Build and push
        uses: docker/build-push-action@v5
        if: success()
        with:
          context: .
          push: true
          tags: |
            myapp:latest
            myapp:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

      - name: Generate SBOM
        uses: docker/scout-action@v1
        with:
          command: sbom
          image: myapp:latest
          output: sbom.json
          format: spdx-json

      - name: Upload SBOM
        uses: actions/upload-artifact@v4
        with:
          name: sbom
          path: sbom.json

GitLab CI 示例

stages:
  - build
  - scan
  - push

variables:
  DOCKER_TLS_CERTDIR: "/certs"

build:
  stage: build
  image: docker:27-dind
  services:
    - docker:27-dind
  before_script:
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
  script:
    - docker buildx build
      --cache-from=type=local,src=/tmp/buildx-cache
      --cache-to=type=local,dest=/tmp/buildx-cache
      -t $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
      .
  cache:
    paths:
      - /tmp/buildx-cache

scan:
  stage: scan
  image: docker:27
  script:
    - docker scout cves
      --exit-code 1
      --severity HIGH,CRITICAL
      $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
  allow_failure: false

push:
  stage: push
  image: docker:27
  script:
    - docker push $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
    - docker scout sbom
      --output sbom.json
      $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
  artifacts:
    paths:
      - sbom.json
  only:
    - main
