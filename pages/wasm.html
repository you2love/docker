🔮 WASM 容器完整教程 (2026)

掌握下一代容器技术：WebAssembly 在 Docker 中的应用

⚠️ 重要提示：WASM 已被废弃

WebAssembly (WASM) 工作负载已被标记为废弃，将在未来的 Docker Desktop 版本中移除。

  • 废弃时间：Docker Desktop 4.55.0 (2025-12-16)
  • 移除计划：未来的 Docker Desktop 版本
  • 维护状态：不再积极维护
  • 建议：对于新项目，建议使用传统 Linux 容器或其他替代方案

本页面保留用于参考和已有 WASM 项目的维护，但不建议在新的生产环境中使用。

什么是 WASM 容器？

WebAssembly (WASM) 容器是 Docker 的革命性特性，它将 WASM 模块作为容器运行。WASM 最初为浏览器设计，现在已成为云原生的下一代运行时技术。

为什么需要 WASM 容器？

📦 传统容器的局限

  • 镜像体积大（通常 100MB-1GB）
  • 启动慢（秒级）
  • 资源占用高
  • 安全隔离依赖内核
  • 跨平台需要多架构构建

✨ WASM 容器的优势

  • 镜像极小（通常 <1MB）
  • 毫秒级启动
  • 内存占用极低
  • 沙箱隔离，更安全
  • 一次构建，随处运行

性能对比：WASM vs 传统容器

安全隔离 命名空间 能力模型 + 沙箱 更强

安装和配置 WASM 支持

⚠️ 注意：以下步骤仅供参考，因为 WASM 工作负载已被废弃。如果您正在开发新项目，建议考虑其他方案。

1

更新 Docker

需要 Docker Desktop 4.25+ 或 Docker Engine 27.0+

# 检查 Docker 版本
docker --version
# 需要 v27.0 或更高

# 更新 Docker Desktop（macOS/Windows）
brew upgrade --cask docker-desktop

# Ubuntu/Debian
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io
2

启用 WASM 支持

# 方法一：在 Docker Desktop 中启用
# 设置 → General → Enable WebAssembly

# 方法二：通过配置文件
# ~/.docker/daemon.json
{
  "features": {
    "wasm": true
  }
}

# 方法三：临时启用（实验性）
export DOCKER_CLI_EXPERIMENTAL=enabled
3

安装 WASM 运行时

Docker 支持多种 WASM 运行时：

# 安装 WasmEdge（推荐）
curl -sSf https://raw.githubusercontent.com/WasmEdge/WasmEdge/master/utils/install.sh | bash

# 安装 Spin（Fermyon）
curl -fsSL https://developer.fermyon.com/downloads/install.sh | bash
sudo mv spin /usr/local/bin/

# 安装 WASI 节点
npm install -g @aspect-build/wasi-node

# 验证安装
docker info | grep -i wasm
# 应显示：wasm: wasmedge 或 wasm: spin
4

验证 WASM 支持

# 检查 WASM 运行时
docker info | grep -A 5 "Runtimes"

# 输出示例：
# Runtimes: io.containerd.wasmedge.v1 wasmtime spin
# Default Runtime: runc
# WASM Runtimes: wasmedge, spin

# 运行测试 WASM 容器
docker run --runtime=io.containerd.wasmedge.v1 \
  --rm wasmcloud/http-hello-world

运行 WASM 容器

示例 1：运行现成的 WASM 应用

# 运行 Hello World WASM 应用
docker run --rm \
  --runtime=io.containerd.wasmedge.v1 \
  -p 8080:8080 \
  wasmcloud/http-hello-world

# 访问 http://localhost:8080

# 运行 Redis 的 WASM 版本（极轻量）
docker run --rm \
  --runtime=io.containerd.wasmedge.v1 \
  -p 6379:6379 \
  wasmtime/redis-wasm

# 查看容器状态
docker ps --filter "runtime=io.containerd.wasmedge.v1"

示例 2：构建和运行自定义 WASM 应用

使用 Rust 和 Spin 框架创建 WASM 应用：

# 1. 安装 Spin 框架
curl -fsSL https://developer.fermyon.com/downloads/install.sh | bash
sudo mv spin /usr/local/bin/

# 2. 创建新的 Spin 项目
spin new hello-wasm
# 选择模板：http-rust

# 3. 进入项目目录
cd hello-wasm

# 4. 构建 WASM 模块
spin build

# 5. 使用 Docker 构建镜像
docker buildx build \
  --platform wasi/wasm \
  -t my-wasm-app \
  -f Dockerfile.wasm .

# 6. 运行 WASM 容器
docker run --rm \
  --runtime=io.containerd.wasmedge.v1 \
  -p 3000:3000 \
  my-wasm-app

WASM Dockerfile 示例

Rust + Spin 示例

# syntax=docker/dockerfile:1.7
# WASM 应用的 Dockerfile

# 构建阶段
FROM rust:1.75 AS builder
WORKDIR /app

# 安装 Spin CLI
RUN curl -fsSL https://developer.fermyon.com/downloads/install.sh | bash
ENV PATH="/root/.local/share/spin/bin:${PATH}"

# 复制项目文件
COPY Cargo.toml Cargo.lock ./
COPY src/ ./src/
COPY spin.toml .

# 构建 WASM 模块
RUN cargo build --release --target wasm32-wasi

# 运行阶段（使用 WasmEdge）
FROM scratch
WORKDIR /app

# 从构建阶段复制 WASM 文件和配置
COPY --from=builder /app/target/wasm32-wasi/release/hello_wasm.wasm ./
COPY --from=builder /app/spin.toml .

# 使用 WasmEdge 运行时
# 注意：实际运行时需要 Docker 配置 WasmEdge 运行时
CMD ["spin", "up"]

# 标注为 WASM 应用
LABEL org.opencontainers.image.title="WASM App"
LABEL org.opencontainers.image.base.name="scratch"

AssemblyScript 示例

# AssemblyScript WASM 应用
FROM node:20-alpine AS builder
WORKDIR /app

# 安装 AssemblyScript

Go + TinyGo 示例

# Go WASM 应用（使用 TinyGo）
FROM golang:1.21-alpine AS builder
WORKDIR /app

# 安装 TinyGo
RUN wget https://github.com/tinygo-org/tinygo/releases/download/v0.30.0/tinygo_0.30.0_amd64.deb && \
    dpkg -i tinygo_*.deb

# 复制并构建
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN tinygo build -o app.wasm -target=wasi .

# 运行阶段
FROM scratch
COPY --from=builder /app/app.wasm ./
CMD ["app.wasm"]

使用 Docker Compose 编排 WASM 服务

# docker-compose.wasm.yml
name: wasm-microservices

services:
  # WASM API 服务
  wasm-api:
    build:
      context: ./api
      dockerfile: Dockerfile.wasm
    runtime: io.containerd.wasmedge.v1
    ports:
      - "8080:8080"
    deploy:
      resources:
        limits:
          cpus: '0.5'
          memory: 50M
        reservations:
          cpus: '0.1'
          memory: 10M
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://localhost:8080/health"]
      interval: 10s
      timeout: 5s
      retries: 3
      start_period: 5s

  # WASM 前端服务
  wasm-frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile.wasm
    runtime: io.containerd.wasmedge.v1
    ports:
      - "3000:3000"
    depends_on:
      - wasm-api
    deploy:
      resources:
        limits:
          cpus: '0.5'
          memory: 30M
    restart: unless-stopped

  # 传统容器（数据库）
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    deploy:
      resources:
        limits:
          cpus: '1'
          memory: 200M

  # 另一个 WASM 服务（边缘计算）
  wasm-edge:
    image: wasmcloud/http-hello-world
    runtime: io.containerd.wasmedge.v1
    ports:
      - "8081:8080"
    deploy:
      resources:
        limits:
          cpus: '0.25'
          memory: 20M
    restart: unless-stopped

volumes:
  redis-data:
    driver: local

networks:
  default:
    driver: bridge

Compose 命令

# 启动所有服务
docker compose -f docker-compose.wasm.yml up -d

# 查看服务状态
docker compose -f docker-compose.wasm.yml ps

# 查看日志
docker compose -f docker-compose.wasm.yml logs -f wasm-api

# 停止所有服务
docker compose -f docker-compose.wasm.yml down

# 查看资源使用
docker stats --filter "runtime=io.containerd.wasmedge.v1"

实战：用 Rust 构建 WASM 微服务

步骤 1：创建 Rust 项目

# 创建新的 Rust 项目
cargo new wasm-microservice
cd wasm-microservice

# 添加 Spin 依赖
cargo add spin-sdk
cargo add serde serde_json

步骤 2：编写 WASM 应用

// src/lib.rs
use spin_sdk::http::{Request, Response};
use spin_sdk::http_component;

#[http_component]
fn handle_wasm_microservice(req: Request) -> anyhow::Result {
    let path = req.uri().path();
    
    match path {
        "/health" => Ok(Response::builder()
            .status(200)
            .header("content-type", "application/json")
            .body(Some(r#"{"status":"healthy"}"#.into()))?),
        
        "/api/hello" => Ok(Response::builder()
            .status(200)
            .header("content-type", "application/json")
            .body(Some(r#"{"message":"Hello from WASM!"}"#.into()))?),
        
        _ => Ok(Response::builder()
            .status(404)
            .body(Some(r#"{"error":"Not found"}"#.into()))?),
    }
}

步骤 3：配置 Spin

# spin.toml
spin_manifest_version = 2

[application]
name = "wasm-microservice"
version = "1.0.0"

[[trigger.http]]
route = "/..."
component = "wasm-microservice"

[component.wasm-microservice]
source = "target/wasm32-wasi/release/wasm_microservice.wasm"
allowed_http_hosts = []
[component.wasm-microservice.build]
command = "cargo build --target wasm32-wasi --release"
watch = ["src/**/*.rs", "Cargo.toml"]

步骤 4：构建和运行

# 添加 WASM 目标
rustup target add wasm32-wasi

# 本地测试
spin up

# 使用 Docker 构建
docker buildx build \
  --platform wasi/wasm \
  -t wasm-microservice \
  -f Dockerfile.wasm .

# 运行容器
docker run --rm \
  --runtime=io.containerd.wasmedge.v1 \
  -p 8080:8080 \
  wasm-microservice

# 测试 API
curl http://localhost:8080/health
curl http://localhost:8080/api/hello

WASM 容器适用场景

⚡

Serverless/FaaS

毫秒级冷启动，完美适配函数计算场景

示例： AWS Lambda, Cloudflare Workers
🌐

边缘计算

小体积、低资源，适合边缘节点部署

示例： CDN 边缘函数，IoT 网关
🔌

插件系统

安全沙箱，适合第三方代码执行

示例： Envoy 过滤器，数据库扩展
📊

数据处理管道

轻量级、可组合，适合数据转换

示例： 日志处理，数据清洗
🔐

安全敏感应用

强隔离性，防止代码逃逸

示例： 加密计算，隐私保护
🎮

游戏服务器

快速扩缩容，低延迟响应

示例： 实时对战，游戏逻辑

WASM 最佳实践

✅
选择合适的运行时

WasmEdge 适合通用应用，Spin 适合 HTTP 服务，Wasmtime 适合嵌入式

✅
优化 WASM 模块大小

使用 release 构建，启用 LTO，移除调试信息

✅
合理配置资源限制

WASM 资源占用低，但仍需设置合理的 CPU 和内存限制

✅
使用健康检查

WASM 启动快，健康检查间隔可以设置更短

✅
混合部署

WASM 适合无状态服务，数据库等有状态服务仍用传统容器
